Design notes

Try these
Search consolidation (mixed exact and related passages), error (recoverable failure), nothing (no matches), everything (capped at 1,000 candidates). Open a result, use Previous/Next, then Back to results. Pause/resume the 910-page handbook; retry the failed paper; relink the missing scan; remove a document and Undo; visit the Removed scope to restore or delete. Use the Tweaks panel to start empty, fail saves, or speed up processing.
Hierarchy
One search field spans the whole view because finding a passage is the primary job. The list keeps rows to two lines: title with an Open marker, then authors · year · pages · tags in muted type. Status lives in its own column so stable documents read as quiet text (“910 searchable passages”) while active work gets a thin stage bar and attention states get the accent. Counts sit under the title as a sentence, not a stat row.
Interaction
Single-click selects (details load on demand in the right pane); double-click, Enter or the arrow button opens, reusing an existing tab. Searching turns the list itself into results, grouped under each document's title and authors, so the view stays full width until a result is clicked; that opens a page preview on the right with an Open in reader action. Back to library restores the normal list. Results group by document with page targets visible; exact matches are marked in the snippet, meaning-based matches are labelled “Related passage” with no fake word highlight. Opening a result shows a locating state; the latest click always wins. The reader's highlight is an accent outline with a margin label, distinct from saved notes (grey underline), and is never saved. Close tab, Remove (undoable, then Removed scope), Restore and Delete permanently are separate actions with separate copy.
What's what
PreservedLibrary list, Add PDFs (multiple), open/closed state, processing states and actions, passage search with paged loading and the 1,000 cap, all seven filters with one typed property condition, metadata editing, remove/restore/permanent delete, relink. ProposedLibrary-wide properties (text, number, select, formula) created from the table header or the document panel; agentic filling per property with chosen inputs and an editable system prompt, run per cell, per selection or per column; row selection with bulk actions; pinnable and resizable columns; tag consolidation (manual merge/rename/delete or agentic suggestions you accept); fill empty metadata from the file; Get PDF for imported references (local file or open-access search); non-PDF sources — video and podcast transcripts by timestamp, web article snapshots, generated image descriptions — all searched as passages. Scope tabs (All / Open / Needs attention / Removed), results grouped by document, right-pane Results · Details · Activity, chip inputs replacing semicolon fields, Undo toast, keyword-available wording during indexing, mismatch guard on relink, blocked-deletion explanations. FutureUser-defined databases with relations, rollups, formulas and saved views.
Themes and access
The layout borrows from reference managers (Zotero/Mendeley columns: item type, authors, year, publication, tags, collection, date added) and from Notion (sidebar of collections and tags, view tabs, typed property headers, a side peek page with icon · label · value rows). Light theme follows Modernist tokens (Archivo, red accent) with softened radii; dark follows Nocturne (Inter, blurple accent). Both are driven by the same tokens, so every surface, rule and control swaps together. Nothing animates continuously; progress bars only move when work happens. All controls are keyboard reachable with a visible accent focus ring.
