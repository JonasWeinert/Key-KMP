# Canonical library implementation status

2026-09-11. Working implementation in the tree; not a declaration that every performance and rollout gate in the PRD is complete.

## Implemented

- `key-library`: ordinary bundled SQLite through rusqlite, WAL, foreign keys, durable transactions and nine numbered migrations, with a consistent SQLite backup before upgrading an existing schema. The database is `<Tauri app data>/semantic-search/library.sqlite3`.
- Managed originals in `semantic-search/sources/<SHA-256>.pdf`. Backend verifies incoming hashes. Source reopening revalidates bytes. Canonical identities survive filename changes and duplicate imports. SQLite/index paths resolve filesystem aliases consistently.
- Canonical document metadata, annotations/comments, arbitrary scalar properties, normalized semantic block text, byte-offset passages, compact passage rectangles, compressed page structure and native page geometry. Scientific analysis, references, citations and enrichment results are persisted as versioned SQLite artifacts.
- Title/authors/year editing, document-scoped ordered author rows, user-edit observations, tags/collections, and typed property editing/filtering. Metadata/comment/property/label phrase filters use SQLite FTS5 with transactional synchronization. References and citations also have queryable relational rows. SQL selects eligible documents before keyword or vector retrieval.
- Annotation mutation transactions preserve unrelated annotations. New annotations capture page geometry alongside character ranges and quoted text. Legacy localStorage annotations migrate when the corresponding PDF is opened; receipts prevent deleted annotations from being resurrected. Legacy JSON library records remain visible with a relink action; original manifests stay untouched.
- Tantivy postings/positions with canonical passage IDs and no duplicate stored body text. A read-only adapter avoids the upstream adapter's per-query writer allocation. One indexing writer uses a 15 MB heap and one thread. Keyword shards use shared BM25 statistics, verified against a single combined index.
- Frankensearch vector generations with model-artifact fingerprints and corpus fingerprints. Keyword readiness is independent of embeddings, and keyword search works when the model is unavailable. Immutable generation directories are published via SQLite pointers after verification. Old generations remain available to readers.
- Bounded candidate lists per modality, merged across eligible documents before reciprocal-rank fusion. This removes the incorrect comparison of separately fused per-document rank-one scores. Final snippets and targets are hydrated through a reused SQLite connection. Cursor pages use short-lived, bounded snapshots of IDs/scores: 30 results per page, at most 1,000 candidates, four snapshots and a five-minute expiry.
- A bounded query worker uses a shared embedding helper process; ONNX no longer runs in the app query thread. The helper releases its model after 30 seconds idle. Repeated query embeddings are reused. Embedding batches use a persistent content/producer cache, allowing retries without recomputing completed vectors. Batches of eight reduce measured ONNX peak memory; the vector builder reads cached vectors through a reusable SQLite connection instead of retaining a second embedding map. Parent-side semantic/chunk buffers are released before waiting for indexing.
- Durable document stage/count/error state and pause/resume/retry controls. Interrupted queued/processing/indexing documents resume on app startup from managed originals. Closing a reader does not cancel its indexing. Renewable SQLite stage leases exclude concurrent helper owners, expire after crashes and use compare-and-swap renewal/release. Pause terminates supervised extraction and vector helpers; completed embedding batches survive. A separate native-completion checkpoint resumes unfinished enrichment even when vectors were already published. Imports interrupted before descriptor creation reconstruct it from the managed source.
- `key-processing` has a fixed two-worker pool, reader priorities, queue deduplication and background aging, with at most one semantic job active to reserve reader capacity. Reference network work has its own single-worker queue. Queued work retains source paths rather than PDF buffers. Native extraction writes pages directly to SQLite with a bounded PDFium text cache. In-document native search reads one page at a time. Routine progress responses omit unchanged scientific analysis and never include the semantic document.
- PDF.js loads page proxies lazily and paints before companion analysis completes. New files render from Blob URLs while at most two sequential binary imports stream SHA-256 with 4 MiB backpressure; additional files queue and split views share pending imports. Managed PDFs reopen via bounded native range reads. PDFium opens files directly, and hashing uses a 64 KiB buffer. Native reader text overlays retain a small page working set, preserving active selections and visible pages.
- Search hits open a managed PDF or reuse its existing tab, load the correct page dimensions, and paint a separate transient result overlay. Back/previous/next/dismiss controls preserve query, filters and results. Async navigation uses a request token to reject stale responses.
- Soft removal hides documents from queries without deleting originals or annotations; a removed-documents view restores them across restarts. Missing/damaged index pointers are invalidated with a retryable document error while healthy indexes remain searchable. Startup garbage collection removes only unreferenced generation directories older than seven days; current/fresh generations and originals remain intact.

## Remaining PRD work and limitations

1. Raw semantic pages now stream into reconstruction and have durable restart checkpoints. Document-wide semantic reconciliation still retains reconstructed pages. The app now reads canonical semantic pages incrementally, and index input uses a rewindable disk spool. Frankensearch builders are bounded to 2,048-passage segments; document-wide reconciliation and a total process-tree memory ceiling remain open. OCR is explicitly outside this PRD.
2. The scheduler has bounded workers, priority aging, independent reference enrichment, helper leases, cancellation, available-memory admission and preemption for a newly selected reader. Ten small real-PDF jobs passed the active-reader ordering test. Whole-document reconciliation is not cooperatively time-sliced. Checkpointed extraction and embedding work rotates after a 15-second quantum when another document is pending; only newly durable work triggers rotation, avoiding cached-prefix restart loops. CPU-pressure and recent-interaction admission are implemented. Whole-document reconciliation/final vector publication remain non-preemptible by the fairness quantum.
3. Lexical scores use shared corpus statistics; retrieval still opens document shards in two passes, but index-pointer reads now reuse one SQLite connection. A synthetic 100-document/100,000-passage lexical benchmark passed below 500 ms p95 after this change. Real-corpus hybrid latency while indexing, a shared corpus index and exhaustive pagination remain unqualified. Pagination is explicitly capped at 1,000 candidates.
4. Author authority identities and provider observation/override resolution remain incomplete. User edits have observations; extracted provider metadata retains its existing source fields. References/citations have relational JSON rows, but there is no public generic filter language over all extraction fields (a stated non-goal).
5. Schema 7 migrates high-volume content to integer links and a 32-byte content-digest registry, interns artifact namespaces and preserves public IDs. The populated-v6 upgrade and 100k-passage migration passed integrity/anchor checks. Low-volume metadata foreign keys still use text hashes; a bounded priority writer actor, checksummed binary native-page/embedding artifacts and transactional semantic page batches are implemented. Some lifecycle/lease writes still use direct short transactions. Passage rectangles remain packed u16.
6. Soft deletion and old-generation collection are implemented. Malformed legacy manifests are preserved and recorded as maintenance errors without blocking library startup. Permanent canonical/source/index deletion uses a tombstone and durable filesystem cleanup queue; stale workers cannot reinsert deleted documents. Comprehensive crash-injection coverage and legacy annotation migration tooling remain open. Unresolved legacy records cannot reconstruct unavailable source PDFs.
7. A debug macOS app bundle was built and its native pipeline exercised. This is not a notarized release or a claim that large-document, corpus-scale, repeated-navigation memory-plateau and release-percentile gates have passed.

## Process-isolation follow-up (2026-09-10)

- Interactive PDFium now lives in a supervised child with framed IPC, binary pixel replies, cancellation, a 32-request bridge queue, a 30-second response timeout and lazy handle recovery. The bridge retains at most four native documents, reopening inactive ones from paths. Restart descriptor reconstruction also uses this service and runs off the UI setup path.
- The shared ONNX service accepts at most eight concurrent requests, batches at most eight inputs, caps serialized RPCs at one MiB, prioritizes queries and unloads idle model state. An owned-parent pipe ends its lifetime after app exit. Query clients recover a killed service and verify the restarted model identity; query failures preserve keyword retrieval.
- Reader activation reprioritizes semantic work. Disposable helpers yield to a newer selected queued reader; raw-page/embedding checkpoints allow resumption. Memory admission reserves system headroom. This is a soft admission policy, not a hard OS/GPU memory limit.
- Visible-page discovery uses binary search. Active panes share the default tile-cache budget, obsolete zoom grids lose protection offscreen, and old render completions cannot remove a newer pending request with the same key.
- A ten-job real-PDF helper run selected the last queued document; it finished first. All jobs completed in about 35.4 seconds, all ten filtered vector-only probes passed, and the sampled processing-tree peak was about 372 MiB. These are ten variants of a seven-page fixture, not large/scanned-document qualification.
- A 100-document/100,000-passage synthetic storage migration took about 1.0 seconds, preserved all rows/anchors and passed integrity checks. Live SQLite pages fell from 60.2 MB to 11.1 MB. This is live page usage, not a claim that migration immediately shrinks the physical file without compaction.
- On the same synthetic-size lexical corpus, p95 improved from about 581 ms to 317 ms after reusing the index lookup connection. Selective year-filter p95 was about 27 ms. These measurements are debug, lexical-only and not collected with concurrent indexing.
- The actual interactive helper returned a seven-page descriptor, 3,642 characters on page one, 262,144 binary pixel bytes and rejected a pre-cancelled render.
- The real embedding recovery probe killed the model child and passed a subsequent vector-only query. Reopening the prior corpus embedded zero chunks and rebuilt no index.
- Chromium stress completed 20 scroll/zoom cycles and ten replacements. The last ten interaction samples were about 1,193–1,198 MiB for the browser tree; replacement samples were about 1,197–1,209 MiB, against a browser baseline around 915 MiB. The tile working set remained around 96 MiB (with a transient one-tile insertion overshoot). This is evidence of warm retention behavior, not a WebKit or whole-app memory guarantee.

Database walkthrough and proposed user-defined tables/properties/relations: [database-model-and-process-design.md](database-model-and-process-design.md). The logical table editor and generic relation/property model are proposals for discussion, not shipped UI.

## PRD follow-up (2026-09-11)

- The app's cold semantic helper now publishes canonical pages directly. Reopening/index preparation hydrates one page at a time into a rewindable framed disk spool. Embeddings still use batches of eight and vector segments of 2,048. The helper consumes reconstructed pages when producing DTOs, avoiding a second full-document geometry copy. Cross-page reconciliation itself still retains reconstructed pages.
- A per-root, per-process writer actor uses bounded queues and reserves interactive capacity. Semantic page structure and passage anchors commit together. Native-page and embedding artifacts use a versioned, checksummed binary envelope; legacy compressed JSON remains readable. Corrupt derived page/vector artifacts are discarded for rebuilding; native text requests can repair a missing page from the managed source.
- SQLite was upgraded from 3.51.1 to bundled 3.53.2 after a concurrency run reproduced a native Unix WAL-lock deadlock. The dependency now includes the upstream WAL locking/reset fixes; a version guard prevents regression.
- CPU/memory admission and short interaction deferral supplement fixed worker caps. Extraction/embedding helpers rotate after 15 seconds when another document waits and a new durable checkpoint exists. Cached-prefix replay does not trigger another yield. Reconciliation and final vector publication still run to completion, subject to the stall timeout.
- Permanent deletion uses schema-8 tombstones and a durable filesystem cleanup queue. Background companion records are distinguished from open readers. Filesystem cleanup runs off the UI thread. Queries and publishers take a shared cross-process generation pin; collection uses an exclusive nonblocking pin, and permanent filesystem cleanup waits for readers.
- Page DOM attachment now follows the viewport. Browser text search scans pages incrementally, text overlays have a bounded working set, and offscreen PDF.js page resources are cleaned when idle. The 1,000-page stress test fell from roughly 3 GB at cycle six to roughly 1.26 GB after ten cycles, including a roughly 0.92 GB browser baseline. This is measured retention, not an unconditional limit.
- Qualification exposed dropped/reversed semantic text on rotated PDFs and incorrect CropBox/rotation transforms in the PDF.js fallback text layer. Both were fixed. Extraction uses an analysis-only unrotated copy when necessary, then transforms anchors back to the source viewport. The four-orientation fixture now has 128 passages; all four canonical highlights overlap independently rendered PDF.js text bounds by about 97%, and every screenshot was inspected. Extraction/index versions invalidate older results.
- Ten distinct PDF jobs completed in 33.1 seconds, with the selected document first in 2.18 seconds and ten successful filtered vector-only queries; continuously sampled processing-tree peak was 315.8 MiB. The mixed 1,000-page-plus-nine-paper run completed in 43.3 seconds, selected the short reader first in 4.55 seconds, and passed all filtered vector queries. During all ten overlapping viewer cycles, no sampled frame exceeded 20 ms and no exact render timed out. Indexer cycle samples reached 448.5 MiB; this is not its continuous peak.
- The 51 MB image-only fixture completed as `no_text` with zero passages instead of an indefinite indexing state. OCR remains outside the PRD.

Full evidence: [prd-followup-validation-2026-09-11.json](prd-followup-validation-2026-09-11.json). This follow-up closes substantial implementation and qualification gaps, but does not mark the entire PRD complete. The numbered limitations above remain authoritative where not superseded here.

## Publication recovery follow-up

Schema 9 journals verified, checksummed generation publication before swapping the canonical pointer. Restart validates the immutable files and conditionally replays the intent against the previous pointer; superseded intents cannot replace newer results, corrupt intents are discarded with a maintenance record, and paused work waits. Lexical readiness commits with publication. Garbage collection protects pending intents as well as published generations. Targeted tests cover reopen between intent and publication, supersession, corruption, pause/resume and removal. This closes the missing durable publication-journal implementation; comprehensive fault injection remains a separate qualification task.

The embedding service now has a 10-second bootstrap deadline and a bounded address reply. Permanent-delete UI rejects any open document tab, including nonresident tabs, and suppresses duplicate submissions.
